# 长文本来源与候选分集实施

依据：CR-029、CR-090/091/092/094/095 与 `production-recovery-requirements.md`。完整产品目标保持不变；此阶段交付长文本来源和候选确认的基础，随后继续逐场映射、局部恢复及 AI 长文本编排。

## 已核实的问题

- `split_remaining` 只从已分配范围的最大结束位置继续，中间章节先被分配后，前面的未覆盖原文被跳过。内存直接调用已复现：未覆盖开头 19 字，候选却从第 37 字开始。
- 分集来源使用路径、摘要、起止位置，缺少可读取的历史来源快照和稳定章节身份。文件改变后只能提示来源变化，不能从原链接重读旧来源。
- 分集预览仅存在当前组件，采用后依赖自动保存；工作稿需另行建立。尚未形成持久候选、确认、原请求恢复和来源追溯的完整路径。

## 产品决策

1. 为采用的来源保存不可变规范化快照（NFC、LF、Unicode 码点坐标）。章节以快照身份、位置及内容确定身份；重复标题不能合并为同一章。明确章节标题、前言和无标题正文。
2. 对整份来源计算已覆盖与未覆盖区间，支持选择章节并预览分集。跨过已用内容的间隙不能伪装成一个连续来源范围；集数不足时明确要求调整，不静默丢文。
3. 持久保存候选方案及来源版本。规则分集明确标为规则建议，不冒充 AI 语义改编。标题、时长和范围可调整，显示章节、片段和未覆盖量。
4. 显式确认后追加新分集并建立单集 SQL 工作稿；原有集保持内容和顺序，不改名、不重排。预算仅沿用原值，新集不自动增加消费限额；不调用付费模型。
5. 使用现有分集文件锁及 SQL 项目锁。持久文件回执允许文件写入后 SQL 失败的原请求恢复；确认记录、来源链接、工作稿、审计和 outbox 使用同一 SQL 事务。确认与重发必须匹配当前权限、原计划和完整请求。
6. 当前会话保留候选修改和待确认原请求；刷新只读取，响应不确定时显式重发原键和原内容，禁止换方案后暗中重放。撤权后不显示缓存正文。
7. 工作稿来源可打开旧快照，即使当前文件变化；新增来源信息通过可选字段兼容既有工作稿。逐场人工/模型映射及局部版本恢复另行完成，不以整集来源代替。
