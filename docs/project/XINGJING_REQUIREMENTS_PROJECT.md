## 4. 需求状态模型

```text
未开始 → 开发中 → 待验收 → 已验证
                    ↘ 退回开发
任意状态 → 阻断（外部条件或发布门禁未满足）
```

状态规则：

- **未开始**：没有面向该需求的实现分支或测试；
- **开发中**：已有实现，但证据尚不完整；
- **待验收**：实现、自动化测试和迁移已完成，等待阶段级运行验收；
- **已验证**：需求、代码、测试、运行证据和发布门禁全部通过；
- **阻断**：明确记录负责人、解除条件和禁止动作，不把阻断项计入完成度。

## 6. 多端平台能力

以下能力纳入平台地基和 P0/P1，不另起一套不兼容后端：

- 版本化 OpenAPI 和客户端兼容策略；
- 设备会话、令牌轮换、远程下线和安全存储边界；
- 分片上传、断点续传、下载令牌和文件摘要；
- 任务查询、SSE、推送通知、深链和分享；
- 统一错误码、权限语义、任务状态、设计令牌和领域类型；
- 本地缓存、离线冲突、桌面文件和移动端平台能力适配接口。

平台核心完成后，原生客户端可以独立排期开发，不得要求重写身份、项目、任务、账务或合规服务。

## 7. 需求完成证据

每个计入完成度的需求必须关联：

1. v9.2 页面 ID 或共享能力编号；
2. 实现提交；
3. 数据表、API、事件或客户端契约；
4. 单元、集成、契约和必要的端到端测试；
5. 数据迁移与兼容验证；
6. 运行截图、日志、导出包或其他可复现产物；
7. 安全、计费、合规和发布门禁结果。

缺少任何适用证据时，状态最高只能是“待验收”。

## 8. 阶段发布门禁

每个 P 级完成前必须证明：

- 范围内需求全部为“已验证”；
- lint、类型检查、测试和生产构建通过；
- OpenAPI、事件和数据库迁移兼容性通过；
- 多租户隔离、关键权限和审计通过；
- 任务重复、回调重复、超时、取消、恢复和补偿通过；
- 算力冻结、结算、释放、退款和流水守恒通过；
- 正式导出合规门禁不可绕过；
- 备份、恢复、监控、告警和发布修复方案可执行；
- 追踪矩阵不存在缺失证据或未关闭阻断项。

## 9. 外部商用门禁

以下事项不阻塞 mock、沙箱和测试环境开发，但未满足时禁止相应商用行为：

| 门禁 | 未满足时禁止 |
|---|---|
| 模型供应商合同与 POC | 向真实用户开放付费模型 |
| 支付与退款通道 | 真实收款和自动退款 |
| 审核供应商或自研规则评测 | 自动放行正式内容 |
| 法务合规意见 | 商用正式导出和外部发布 |
| 生产云、对象存储和区域确认 | 落地真实生产数据 |
| 企业 SSO/私有化合同 | 承诺客户特有协议和 SLA |

## 10. 文档同步规则

1. 本文件维护阶段快照和里程碑；
2. 每次功能开发、修复或验收必须更新 `docs/project/requirements/modules/` 或 `shared/` 中对应需求项；
3. 新增、修改、删减、延期和阻断必须同步 `requirements/05-变更与缺口清单.md`；
4. 模块不得按单页孤立判定完成，必须通过 `requirements/06-依赖关系与联合验收.md` 中对应验收包；
5. 标记“已验证”前必须登记实现、自动化测试、运行证据和适用门禁；
6. 提交前运行 `scripts/Test-RequirementsLedger.ps1` 和 `scripts/Test-ProductBaseline.ps1`。
