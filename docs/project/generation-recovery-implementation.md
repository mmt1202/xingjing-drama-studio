# 生成任务核验实施方案

目标：管理员能够在当前工作区查看生成任务的固定输入、占用费用和可信回执，预览影响后恢复已有产物或按已确认的结果结算；未知结果继续保持占用。承接 `production-recovery-requirements.md`，用户已委托产品和实施取舍。

选择持久化回执与处理预览方案。直接在通用后台填写状态会绕过产物和账务校验；仅新增“重试”按钮无法区分上游未完成与本地发布失败。专用核验流程使用现有任务/账本，避免另建一套结算。

## 范围与约束

- `/app/workspaces/{workspaceId}/admin/admin-tasks` 使用专用任务核验页，默认显示需要关注的任务，可切换全部任务及已处理记录。按当前真实工作区隔离，不接收客户端指定跨域身份。
- 查看要求 `admin.business.view` 与 `admin.finance.view`；预览和执行同时要求对应 manage 权限，每个请求实时解析权限。普通创作者不能通过该入口修改生成状态。
- 可信回执由部署的供应商核验适配器签名提交到专用内部入口。签名采用现有生成回调密钥和独立域 `generation-recovery/v1\n`。这证明回执来自可信部署适配器，不能宣传为供应商原生签名；真实适配器核对供应商记录仍需部署验收。
- 回执必须匹配任务、原请求摘要、固定执行身份、供应商/模型、实际调用次数及费用版本。成功回执必须携带已有产物的文件摘要，文件只能从既定执行目录导入；失败回执必须为确定终态，不能将网络超时当作失败。
- 回执不可修改。相反结果、不同供应商身份或不同产物/费用构成冲突；预览后新到达的冲突回执也必须阻止执行。重复相同回执零新增处理。
- 原生图片成功按创建时固定价结算，失败收费为 0；网关回执费用须匹配原 hold，且不能超过原预留。成功产物检查字节摘要、大小、媒体格式；页面不显示服务器路径、凭据或签名。
- 预览固定任务版本、回执身份和资金影响，10 分钟有效。执行提交说明与预览 ID；任务、结算、处理结果、供应商证据和审计同一事务落库。重复执行返回原结果；不能通过换键再次结算。
- 新绑定任务和可证明身份的原生执行支持处理；无身份的历史占用不推测归属。待核验与本地发布待恢复不是新的付费生成，执行不调用生成接口。
- 通用后台旧“执行补偿”入口不得继续把自定义字段写入严格校验的任务快照，改为提示使用核验入口。

## 实施顺序

- [x] `server/xingjing_generation_recovery/`：持久回执、预览与幂等处理，受控产物校验，工作区/权限检查，列表详情及签名入口；Alembic 新增三类记录表。
- [x] `server/xingjing_generation_persistence/repository.py`：在现有成功结算及失败释放事务内提供专用提交准备钩子，使处理记录和账务原子提交；`server/xingjing_generation_runtime/runtime.py` 与 `server/app.py` 组合依赖及路由；保护旧后台入口。
- [x] `frontend/src/xingjing_generation_recovery/`：任务列表、详情、回执冲突、费用影响预览、处理说明、确认与原请求恢复，三语文案；`BusinessRouteBridge.tsx` 替换 AD-047 通用表单。
- [x] 隔离 PostgreSQL 与 HTTP 直接验证：签名、跨域、即刻撤权、摘要不符、错误费用、相反回执、预览过期/失效、执行前到达冲突、并发与同键回放、发布文件变化、原生执行隔离和账本守恒。使用已有测试、静态检查、构建、实际 React 与浏览器验证，不新增测试文件、脚本、夹具或快照。
- [x] 本地备份后迁移、只读核对原有 7 份剧本与 112 集，更新证据与验收状态。真实供应商消费与正式用户任务处理不属于隔离验证。

接入约定见 [核验接入与操作](generation-recovery-integration.md)，实际结果见 [验收证据](../evidence/generation-recovery-20261112.md)。可信适配器的供应商查询、未受理的确定证据、历史缺失身份修复及真实付费故障仍需后续接入与验收。
