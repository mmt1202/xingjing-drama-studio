### 页面目标

查看当前工作区可用算力、冻结额、消费流水、充值记录及按项目拆分的成本。

### 入口、前置与退出

- 进入页面前必须解析当前工作区；项目内页面还必须解析项目、剧集或对象上下文。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `算力账单` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看余额/成本/流水
  - 操作：筛选并导出账务数据
  - 操作：发起有审计的财务操作
  - 字段：账户/流水 ID
  - 字段：业务单据号
  - 字段：金额/算力最小单位
  - 字段：冻结/结算状态
  - 字段：关联任务
  - 字段：发生时间
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `CreditAccount`
  - `CreditHold`
  - `CreditTransaction`
  - `Order`
  - `Invoice`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `billing.view`
  - `billing.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：余额、冻结额和流水使用同一结算快照。
  - 空状态：无流水时展示计费说明，不伪造示例金额。
  - 异常态：对账不平、重复回调或退款处理中显示工单/人工复核编号。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/workspaces/{workspaceId}/credit-account`
  - `GET /api/v1/workspaces/{workspaceId}/credit-transactions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 项目负责人、团队财务 能从规定入口进入 `算力账单`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

## 统一支付与退款实现范围

当前入口接专用账单/订单/退款工作台，采用现有货币最小单位台账。支付商品和渠道来自服务端配置；没有真实商品时不展示原型示例充值包，不伪造积分兑换、预算或预计剩余天数。余额与流水来自同一结算快照，UTC 消费趋势/分布不混合币种。

支付经统一网关明确事件核验后入账；退款先预留额度、申请人与审批人分离，处理中保持预留，核验成功才更新退款额与不可变流水。大额退款要求明确阈值与可信 MFA 验证器，缺失条件保持阻断。网络未知结果不等同失败，不可换新单盲目重试。旧直接改账本的现金退款/订单维护和弱 HTTP 回调已封闭；余额补偿保留独立审批入口和原有权限。

新接口在 `/api/v1/workspaces/{workspaceId}/payments` 提供 catalog、orders、订单详情/actions、refunds 及其 actions；统一签名事件为 `/api/v1/payment-gateway/events`。账单读取为 `/api/v1/workspaces/{workspaceId}/billing/workspace`。写入携带稳定幂等键与明确对象版本，当前权限和同库/工作区归属由服务端校验，拒绝 API Key。

本项只支持可核验的新充值订单。缺少来源桶时采用账户版本依据保守拒绝无法证明未消费的退款；订阅/企业合同现金退款、历史渠道补录、credit_micros 和完整额度桶、真实网关/商户/MFA/PostgreSQL/Java 与 D2 联合验收仍开放。详细对接合同见 `docs/payment-gateway.md`，不能将本地注入端口验证记为真实收退款完成。
