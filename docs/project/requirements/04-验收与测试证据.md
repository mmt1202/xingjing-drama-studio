# 星镜剧创验收与测试证据台账

> 权威测试规范：[`test-and-acceptance.md`](../../product/v9.2/11-quality/test-and-acceptance.md)

## 1. 测试层级

| 层级 | 验证对象 | 最低要求 |
|---|---|---|
| 单元测试 | 业务规则、转换、计算、校验 | 正常、边界和失败路径可重复运行 |
| 组件测试 | 页面组件、表单、状态和交互 | 加载、空、成功、失败、禁用、权限状态完整 |
| API 契约 | OpenAPI、错误码、幂等和兼容 | 请求响应符合版本化契约，operationId 唯一 |
| 集成测试 | PostgreSQL、RabbitMQ、Redis、对象存储、服务间调用 | 使用真实依赖或 Testcontainers 验证事务和失败恢复 |
| 迁移测试 | 数据库及 `project.json` 迁移 | 从零、存量、重复执行、中断恢复、兼容读取 |
| 异步测试 | 队列、租约、回调、SSE、补偿 | 重复消息、超时、取消、重启、晚回调和死信 |
| 安全测试 | 多租户、RBAC、文件、密钥和后台操作 | 跨租户 ID、越权、重放、敏感信息和审计覆盖 |
| 计费属性测试 | 冻结、结算、释放、退款和调账 | 账务守恒、幂等和并发一致性 |
| 合规测试 | 授权、审核、AIGC 标识和正式导出 | 服务端门禁不可由 UI 或直接 API 绕过 |
| 端到端 | P0/P1/P2 用户主流程 | 从入口到最终产物，包含异常恢复和证据留存 |
| 性能容量 | 列表、上传、任务和并发生成 | 达到规格阈值且无资源泄漏或队列失控 |
| 构建部署 | lint、类型、测试、制品、部署和回滚 | CI 绿灯、制品可追踪、健康检查与恢复演练通过 |

## 2. 页面通用验收

每个 `CR/TM/AD/CL` 页面至少验证：

1. 路由、标题、导航归属和入口正确；
2. 字段、筛选、排序、分页、操作和响应式布局与规格一致；
3. 加载、空数据、成功、失败、禁用、无权限和会话过期状态完整；
4. 所有写操作有确认、幂等、错误反馈和审计；
5. 权限在服务端执行，跨租户资源不可访问；
6. API、数据、状态机和页面展示一致，刷新和重试不产生重复副作用。

页面详细测试编号取自 `02-页面需求台账.md` 的“测试”列及逐页规格中的六项通用验收。

## 3. 证据编号规则

```text
EV-<需求ID>-<类型>-<三位序号>
```

类型：`IMPL` 实现、`API` 契约、`DB` 数据迁移、`TEST` 自动化、`RUN` 运行、`GATE` 门禁、`DEFECT` 缺陷。

示例：`EV-CR-003-TEST-001`、`EV-BILL-003-GATE-001`。
