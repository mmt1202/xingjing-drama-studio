# 星镜剧创需求与进度台账使用规则

> 适用基线：XJ-WEB-9.2  
> 生效日期：2026-07-15  
> 适用范围：197 个业务页面、共享平台能力、测试验收、发布门禁和需求变更

## 1. 文档职责

| 文件 | 唯一职责 |
|---|---|
| `01-需求总览与完成度.md` | 汇总 19 个功能模块的范围、完成度和联合验收归属 |
| `modules/` | 按功能模块写完整需求；197 个页面需求全部归入模块，不按页面拆文档 |
| `02-逐页需求查询索引.md`、`appendix/pages/` | 保留 197 份清晰的逐页需求附录，供定位字段和交互；不作为独立验收单元 |
| `03-平台共享能力台账.md` | 跟踪不归属于单一页面的平台能力 |
| `04-验收与测试证据.md` | 规定证据格式、测试层级和“已验证”门槛 |
| `05-变更与缺口清单.md` | 记录新增、修改、删减、缺口和阻断 |
| `06-依赖关系与联合验收.md` | 规定模块依赖链、整块验收场景和阶段门禁 |

详细需求正文仍以 `docs/product/v9.2` 为唯一事实源。台账记录状态和证据，不复制一份可能漂移的需求正文。

## 2. 强制状态模型

状态只允许以下五种值：

| 状态 | 定义 | 进入条件 | 退出条件 |
|---|---|---|---|
| 未开始 | 尚无针对该需求的有效实现 | 需求已登记且范围明确 | 有代码、迁移或测试开始落地 |
| 开发中 | 已有实现活动，但交付证据不完整 | 存在实现提交、工作分支或未完成测试 | 实现与适用测试完成后进入待验收；外部条件中断进入阻断 |
| 待验收 | 实现和自动化验证已完成，等待运行或阶段验收 | 代码、契约、迁移及适用自动化测试均通过 | 运行证据和门禁通过后进入已验证；失败则退回开发中 |
| 已验证 | 需求已具备完整、可复现的交付证据 | 满足本文件第 4 节全部适用条件 | 后续回归失败、需求变更或证据失效时退回开发中 |
| 阻断 | 明确条件导致无法继续或无法验收 | 已登记原因、影响、负责人和解除条件 | 阻断解除后回到此前状态 |

禁止使用“部分完成”“基本完成”“大致可用”等不可计算状态。确有局部实现时仍标“开发中”，并在证据或缺口栏写清已完成和未完成部分。

## 3. 完成率计算

需求覆盖完成率：

```text
需求覆盖完成率 = 已验证需求项数 / 197 × 100%
```

共享能力完成率：

```text
共享能力完成率 = 已验证能力数 / 共享能力总数 × 100%
```

阶段完成率只统计该阶段内的“已验证”条目。未开始、开发中、待验收和阻断均按未完成计算。页面 ID 仅用于证明范围完整，不代表验收按页面孤立执行；最终完成以联合验收包通过为准。

## 4. “已验证”强制证据

每项需求必须按适用范围提供以下证据：

| 证据 | 必填内容 |
|---|---|
| 需求 | 页面 ID 或共享能力 ID；权威规格链接 |
| 实现 | Git 提交哈希；关键文件或模块路径 |
| 契约 | API、数据表、迁移、事件、状态机或客户端契约 |
| 自动化测试 | 测试 ID、测试文件、执行命令和通过结果 |
| 运行证据 | 截图、日志、请求响应、导出包、校验摘要或可复现报告 |
| 门禁 | 适用的安全、权限、计费、合规、性能、迁移和发布结果 |

缺少任何适用证据时，状态最高只能是“待验收”。以下情况不得标记“已验证”：

- 页面可以打开，但数据、操作、异常状态或权限未验证；
- 只有前端静态页面或 mock 数据；
- 代码存在但测试未运行或失败；
- 只有手工点击说明，没有可复现步骤和结果；
- ArcReel 已有相似功能，但未映射并通过星镜需求验收；
- 外部供应商、支付、审核或生产基础设施仍阻断正式使用。

## 5. 每次开发的强制更新顺序

1. 开发前：在对应 `modules/` 文档或 `03` 共享能力文档中找到需求 ID，确认前置依赖、状态和联合验收条件。
2. 开发开始：把状态改为“开发中”，登记实现分支或提交范围。
3. 实现完成：补充实现、契约和测试证据；全部自动化验证通过后改为“待验收”。
4. 运行验收：在 `06` 对应联合验收包中执行整块流程；补充运行证据和门禁结果后才改为“已验证”。
5. 发现遗漏：立即在 `05` 登记缺口；不得静默删减需求。
6. 需求变化：先登记变更编号和影响，再修改权威规格、台账、测试和接口契约。
7. 提交前：运行 `scripts/Test-RequirementsLedger.ps1` 和 `scripts/Test-ProductBaseline.ps1`。

## 6. 回归和降级规则

- 已验证条目的验收测试失败时，必须在同一提交中将状态退回“开发中”。
- 需求来源发生 L2-L4 变更时，受影响条目不得继续沿用旧证据。
- 阻断条目不从分母中排除，不允许通过标记阻断美化完成率。
- 暂不做的需求仍保留在台账中，状态标“阻断”，原因写明决策编号和恢复条件。

## 7. 责任边界

| 角色 | 责任 |
|---|---|
| 产品 | 需求范围、优先级、验收语义和变更批准 |
| 开发 | 实现、迁移、契约和实现证据 |
| 测试 | 自动化、运行验收、缺陷复现和测试证据 |
| 架构/安全/运维 | 跨服务契约、安全、性能、部署和恢复门禁 |
| 开发代理 | 每次任务开始和结束时同步台账，不得自行放宽完成标准 |
