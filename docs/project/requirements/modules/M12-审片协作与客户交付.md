## 1. 模块目标与边界

本模块统一承载「审片协作与客户交付」相关需求。模块内页面、接口、数据、权限、异常与验收必须作为同一能力集合维护，不允许只完成可见页面而遗漏服务端规则或失败路径。

- 前置依赖：M08、M09、M10、外链安全
- 下游能力：客户批注、审批和交付确认
- 页面只做范围映射；模块完成必须通过联合验收，不以单页可打开为完成。

### 实现与验证边界（2026-10-22）

- 员工可通过 `POST /api/v1/workspaces/{workspaceId}/review-comments/{commentId}/replies` 回复客户批注；要求可信 `review.manage` 权限，并在当前租户/工作区内查找原批注，沿用原链接、成片版本和时间点。只读成员看不到管理操作。
- 既有上下文 GET 支持 `X-Review-Session-Id`，刷新时不新建会话；缺口令返回明确验证状态，错误口令与失效链接统一隐藏。退出可重试且仅写一次审计，退出后旧会话的读取、媒体与写入均被拒绝。
- 前端不确定失败重试复用幂等键；截图上传全程防重复点击，评论提交成功才清空草稿。已有会话刷新保留草稿；回复按父子关系呈现。
- 验收使用交付记录的当前版本，签收后的结论不可再改写；本地浏览器已覆盖通过、退回、再次通过、签收和退出。
- 客户与员工界面文案统一 zh/en/vi；上下文、动作、视频和截图响应不缓存，截图请求即使不带 Content-Length 也受 10MB 上限约束。
- 未新增数据库表、迁移、测试文件或测试脚本。本地直接 HTTP 使用实际 SQLAlchemy 表及内存 SQLite；UTC 读取适配用于对齐 PostgreSQL 的时间语义。媒体边界使用只读已有文件验证授权与流式返回，不作为真实成片播放验收。

本模块并入「B3 客户审片交付闭环」验收，不单独以页面数量结项。验收至少覆盖：

1. 前置依赖真实可用，权限和租户上下文贯穿全流程；
2. 模块内数据对象、状态机、API 和页面展示一致；
3. 正常、空、失败、冲突、取消、超时、重试和恢复路径按适用范围通过；

5. 下游模块能够消费本模块产物，刷新或重复请求不产生重复副作用。

## 5. 详细功能需求

### CL-001 客户确认交付

- 系统：客户审片
- 路由：`client/client-review-approve.html`
- 阶段：P1
- 当前状态：开发中


| 属性 | 规格 |
|---|---|
| 系统 | 客户审片 Web/H5 |
| 原型路由 | `client/client-review-approve.html` |
| 业务域 | 客户审片 |
| 阶段 | P1 |
| 主要用户 | 客户/甲方审阅者 |

### 页面目标

确认通过、打回修改、补充意见和验收记录签收。

### 入口、前置与退出

- 进入页面前必须验证外链 token、有效期、访问策略和可见版本。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 退出后清理外链会话；返回保持当前审片版本和时间点。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `客户确认交付` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看可审版本
  - 操作：提交时间点反馈
  - 操作：通过或打回受控版本
  - 操作：记录通过/打回结论和签收证据
  - 字段：审片链接/会话 ID
  - 字段：可见版本
  - 字段：有效期
  - 字段：访问策略
  - 字段：时间点批注
  - 字段：审批状态
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `ReviewLink`
  - `ReviewSession`
  - `ReviewComment`
  - `ApprovalRecord`
  - `FinalVideoVersion`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `review.view`
  - `review.approve`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：验证外链有效期、访问策略和可见版本。
  - 协作态：批注提交后显示时间点、提交人和处理状态。
  - 异常态：过期、撤销、超限、版本删除分别给出明确结果且不泄露项目信息。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/review-links/{token}/context`
  - `POST /api/v1/review-links/{token}/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 客户/甲方审阅者 能从规定入口进入 `客户确认交付`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

### TM-002 客户审片链接管理

- 系统：团队
- 路由：`team/team-client-link-management.html`
- 阶段：P1
- 当前状态：开发中


| 属性 | 规格 |
|---|---|
| 系统 | 团队/企业后台 |
| 原型路由 | `team/team-client-link-management.html` |
| 业务域 | 团队客户审片 |
| 阶段 | P1 |
| 主要用户 | 团队管理员、项目负责人 |

### 页面目标

统一管理客户外链、访问权限、水印、有效期和反馈状态。

### 入口、前置与退出

- 进入页面前必须解析团队工作区及管理员数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `客户审片链接管理` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看可审版本
  - 操作：提交时间点反馈
  - 操作：通过或打回受控版本
  - 操作：创建、撤销或复制受控访问链接
  - 字段：审片链接/会话 ID
  - 字段：可见版本
  - 字段：有效期
  - 字段：访问策略
  - 字段：时间点批注
  - 字段：审批状态
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `ReviewLink`
  - `ReviewSession`
  - `ReviewComment`
  - `ApprovalRecord`
  - `FinalVideoVersion`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `review.view`
  - `review.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：验证外链有效期、访问策略和可见版本。
  - 协作态：批注提交后显示时间点、提交人和处理状态。
  - 异常态：过期、撤销、超限、版本删除分别给出明确结果且不泄露项目信息。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/workspaces/{workspaceId}/review-links`
  - `POST /api/v1/workspaces/{workspaceId}/review-links`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 团队管理员、项目负责人 能从规定入口进入 `客户审片链接管理`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。
