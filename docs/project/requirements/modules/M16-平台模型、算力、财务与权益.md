## 1. 模块目标与边界

本模块统一承载「平台模型、算力、财务与权益」相关需求。模块内页面、接口、数据、权限、异常与验收必须作为同一能力集合维护，不允许只完成可见页面而遗漏服务端规则或失败路径。

- 前置依赖：任务、模型供应商、账务与审计
- 下游能力：生成路由、计费、订单和财务运营
- 页面只做范围映射；模块完成必须通过联合验收，不以单页可打开为完成。

## 4. 联合验收要求

本模块并入「D2 模型算力财务闭环」验收，不单独以页面数量结项。验收至少覆盖：

1. 前置依赖真实可用，权限和租户上下文贯穿全流程；
2. 模块内数据对象、状态机、API 和页面展示一致；
3. 正常、空、失败、冲突、取消、超时、重试和恢复路径按适用范围通过；
4. 模块产生的任务、费用、审计、合规和版本证据可以追踪；
5. 下游模块能够消费本模块产物，刷新或重复请求不产生重复副作用。

## 5. 详细功能需求

### AD-004 算力计费

- 系统：平台后台
- 路由：`admin/admin-billing.html`
- 阶段：P0
- 当前状态：未开始


| 属性 | 规格 |
|---|---|
| 系统 | 平台运营后台 |
| 原型路由 | `admin/admin-billing.html` |
| 业务域 | 平台财务与权益 |
| 阶段 | P0 |
| 主要用户 | 平台财务、超级管理员 |

### 页面目标

管理平台算力账户、价格规则、冻结与结算异常、调账和成本核对。

### 入口、前置与退出

- 进入页面前必须验证后台员工独立会话、角色和数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `算力计费` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看余额/成本/流水
  - 操作：筛选并导出账务数据
  - 操作：发起有审计的财务操作
  - 字段：账户/流水 ID
  - 字段：业务单据号
  - 字段：金额/算力最小单位
  - 字段：冻结/结算状态
  - 字段：关联任务
  - 字段：发生时间
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `CreditAccount`
  - `CreditHold`
  - `CreditTransaction`
  - `Order`
  - `Invoice`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `admin.finance.view`
  - `admin.finance.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：余额、冻结额和流水使用同一结算快照。
  - 空状态：无流水时展示计费说明，不伪造示例金额。
  - 异常态：对账不平、重复回调或退款处理中显示工单/人工复核编号。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/admin/finance`
  - `POST /api/v1/admin/finance/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 平台财务、超级管理员 能从规定入口进入 `算力计费`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

### AD-023 模型管理

- 系统：平台后台
- 路由：`admin/admin-models.html`
- 阶段：P0
- 当前状态：开发中
- 证据：EV-M16-MODELS-001；[模型运营验证](../../../evidence/model-operations-20261023.md)

### 页面目标

按原型管理模型身份、能力、参数、凭据引用、有效价格、上下线、工作区路由与健康观测；回调日志和质量看板分别由 AD-021/AD-022 承接，不在此提交生成任务。

### 入口、前置与退出

- 正式路由为 `/app/workspaces/{workspaceId}/admin/admin-models`；沿用既有后台模型入口，并提供创作首页入口。
- 服务端以可信会话验证 `admin.model.view/manage`，API Key 不能作为运营身份；URL 预期工作区必须与当前会话相符。
- 平台模型目录共用，路由策略、审计和本月调用按可信租户及工作区隔离。后台员工独立认证/MFA 仍属后续验收。
- 模型及审计筛选、分页保留在 URL；编辑未保存时禁止内部跳转并保护刷新。滚动恢复不在当前已验证范围。

### 页面区域、字段与操作

- 四项统计展示实际模型总数、健康数、异常/降级数和本工作区本月调用证据数，缺少观测不推算成功率。
- 目录按名称/ID/供应商、媒体、上线及健康状态组合筛选，稳定排序并由服务端分页；卡片显示能力、当前价格、延迟及正在调用/并发上限。
- 接入/编辑表单包含目录 ID、供应商及模型名称、显示名称、版本、区域、媒体、能力、并发上限、凭据引用与参数类型/枚举；已注册的供应商身份不可改写。
- 新模型默认下线；上下线为明确目标状态，变更必须填写原因。上线须有凭据引用和已生效价格。
- 价格发布指定唯一版本、三位币种和正整数最小货币单位，立即生效并保留历史；已接收任务沿用冻结报价。
- 工作区路由指定能力/媒体、允许模型、主模型顺序、优先或权重选择、备用开关、币种/成本及延迟/失败/成功率条件。主模型权重为正整数且合计 100%。
- 详情显示配置版本、UTC 时间转换后的更新时间、真实健康/延迟/并发、凭据配置状态和最近 20 条价格历史。
- 审计支持请求 ID、操作者、对象或原因搜索、时间筛选与分页，展示已脱敏的变更前后记录。

### 数据对象与业务规则

- `ModelDefinition`、`ModelHealth`、`ModelPricing`、`ModelRoutingPolicy`、`ModelCallEvidence`、`ModelCommand`、`ModelAudit` 和 outbox。
- 凭据字段仅接受 `env://` / `secret://` 引用，不接收原始 API Key；读取、回执和审计不返回引用值。保存引用不证明供应商连通。
- 写入携带 `Idempotency-Key`、对象 `version` 与原因；首次创建版本为 0。同键/正文精确重放，不同正文或旧版本返回 409。
- 变更、幂等回执、脱敏审计和 outbox 同事务提交；异常整笔回滚，旧通用模型状态切换入口拒绝写入。
- 路由只选择已上线、有当前价格及凭据引用并满足能力、参数、并发和健康限制的模型；代价比较不得混用币种。
- 降级条件只收紧既有全局连续失败 3 次限制；成功率采用当前工作区最近 20 条终态证据，至少 5 条才应用门槛，观测不足不虚构结论。
- 生成目录、项目默认模型与提交路由使用同一模型数据库；价格和下线无需重启生效。模型与生成库可分别配置，实际适配器/凭据部署仍是调用前置条件。

### 权限与数据范围

- `admin.model.view` 读取目录/策略/审计；`admin.model.manage` 接入、编辑、价格、上下线与策略写入。
- 权限每请求校验；跨工作区预期上下文返回 404，API Key 或无权限身份返回 403。
- 审计记录操作者、时间、对象、请求 ID、原因及脱敏前后摘要；失败请求不生成成功回执。

### 页面状态与异常

- 明确区分权限校验、加载、空目录、筛选无结果、无价格/观测、服务不可用与成功状态。
- 写入失败保留编辑；网络重试复用原幂等键。409 后保留表单并要求显式放弃/重读，避免用旧版本覆盖。
- 列表、详情和审计取消过期读取；缺少迁移或服务配置返回 503 并提供重试。
- 页面配置操作不提交真实模型任务或扣费。

### 接口依赖

- `GET /api/v1/admin/model-control`：目录、组合筛选、分页、统计和当前策略。
- `GET /api/v1/admin/model-control/detail?registryKey=...`：详情及价格历史。
- `GET /api/v1/admin/model-control/audit`：范围内审计搜索、日期和分页。
- `POST /api/v1/admin/model-control/actions`：`upsert_model` / `set_model_active` / `publish_pricing` / `upsert_policy`。
- `GET /api/v1/generation-models` 从同一数据库读取有效目录与默认报价；真实生成沿用既有供应商及计费边界。
- 部署前应用迁移 `a3c955c19e21`；没有修改用户生产数据库。

### 验收标准

1. 按原型呈现目录、统计、详情和路由配置，真实模型/价格/健康回读一致，全部新增文本提供 zh/en/vi。
2. 无权限、API Key、错误工作区和权限即时撤销均被拒绝，凭据引用不出现在响应或审计。
3. 接入、参数、唯一价格版本、上线前置、策略引用、权重及门槛校验有效，失败保留编辑。
4. 同键重试不重复写入，旧版本冲突；审计/outbox 故障整笔回滚，审计可检索。
5. 实际路由遵循优先/权重、备用和健康/代价条件，生成端价格更新与下线即时读取；已接收任务报价和调用释放保持正确。
6. 本地浏览器、SQLite、既有测试与静态检查见 EV-M16-MODELS-001；真实 PostgreSQL、Java 后台身份、供应商及 D2 联合验收后方可晋级已验证。
