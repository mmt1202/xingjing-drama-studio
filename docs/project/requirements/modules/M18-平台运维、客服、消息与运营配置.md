## 1. 模块目标与边界

本模块统一承载「平台运维、客服、消息与运营配置」相关需求。模块内页面、接口、数据、权限、异常与验收必须作为同一能力集合维护，不允许只完成可见页面而遗漏服务端规则或失败路径。

- 前置依赖：平台共享地基、监控、通知与审计
- 下游能力：稳定运营、客服处置、消息触达和策略配置
- 页面只做范围映射；模块完成必须通过联合验收，不以单页可打开为完成。

### AD-040 服务状态监控

- 系统：平台后台
- 路由：`admin/admin-service-status.html`
- 阶段：P0
- 当前状态：未开始


| 属性 | 规格 |
|---|---|
| 系统 | 平台运营后台 |
| 原型路由 | `admin/admin-service-status.html` |
| 业务域 | 平台运维 |
| 阶段 | P0 |
| 主要用户 | 技术运维、超级管理员 |

### 页面目标

查看网关、Java 服务、AI 服务、Worker、存储、Redis、MQ 状态。

### 入口、前置与退出

- 进入页面前必须验证后台员工独立会话、角色和数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `服务状态监控` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看实时指标和异常
  - 操作：调整规则或执行受控操作
  - 操作：确认恢复并关闭事件
  - 字段：服务/队列/事件 ID
  - 字段：环境
  - 字段：指标值
  - 字段：阈值
  - 字段：严重程度
  - 字段：负责人
  - 字段：状态
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `ServiceHealth`
  - `QueueMetric`
  - `AlertRule`
  - `Incident`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `admin.ops.view`
  - `admin.ops.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：展示骨架屏并保留页面结构。
  - 空状态：说明无数据原因并提供当前用户有权限的下一步。
  - 异常态：区分无权限、无数据、服务失败和并发冲突。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/admin/operations`
  - `POST /api/v1/admin/operations/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 技术运维、超级管理员 能从规定入口进入 `服务状态监控`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。
