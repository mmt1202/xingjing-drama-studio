## 1. 模块目标与边界

本模块统一承载「商单、验收与结算」相关需求。模块内页面、接口、数据、权限、异常与验收必须作为同一能力集合维护，不允许只完成可见页面而遗漏服务端规则或失败路径。

- 前置依赖：M10、M11、M12、M09
- 下游能力：商业任务发布、交付、验收和结算
- 页面只做范围映射；模块完成必须通过联合验收，不以单页可打开为完成。

## 4. 联合验收要求

本模块并入「C2 商单履约闭环」验收，不单独以页面数量结项。验收至少覆盖：

1. 前置依赖真实可用，权限和租户上下文贯穿全流程；
2. 模块内数据对象、状态机、API 和页面展示一致；
3. 正常、空、失败、冲突、取消、超时、重试和恢复路径按适用范围通过；
4. 模块产生的任务、费用、审计、合规和版本证据可以追踪；
5. 下游模块能够消费本模块产物，刷新或重复请求不产生重复副作用。

## 5. 详细功能需求

### AD-005 商单详情管理

- 系统：平台后台
- 路由：`admin/admin-commercial-detail.html`
- 阶段：P2
- 当前状态：未开始


| 属性 | 规格 |
|---|---|
| 系统 | 平台运营后台 |
| 原型路由 | `admin/admin-commercial-detail.html` |
| 业务域 | 平台商单 |
| 阶段 | P2 |
| 主要用户 | 商务人员、平台财务 |

### 页面目标

后台查看商单需求、报价、合同、交付、验收和结算。

### 入口、前置与退出

- 进入页面前必须验证后台员工独立会话、角色和数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `商单详情管理` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看需求与节点
  - 操作：提交报价/交付/验收
  - 操作：处理结算或争议
  - 操作：查看对象完整详情与关联记录
  - 字段：商单 ID
  - 字段：客户/承接方
  - 字段：需求范围
  - 字段：金额
  - 字段：里程碑
  - 字段：交付/验收/结算状态
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `CommercialOrder`
  - `CommercialDelivery`
  - `AcceptanceRecord`
  - `Settlement`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `admin.commercial.view`
  - `admin.commercial.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：展示骨架屏并保留页面结构。
  - 空状态：说明无数据原因并提供当前用户有权限的下一步。
  - 异常态：区分无权限、无数据、服务失败和并发冲突。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/admin/commercial-orders`
  - `POST /api/v1/admin/commercial-orders/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 商务人员、平台财务 能从规定入口进入 `商单详情管理`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

  - `Settlement`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `commercial.view`
  - `commercial.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：展示骨架屏并保留页面结构。
  - 空状态：说明无数据原因并提供当前用户有权限的下一步。
  - 异常态：区分无权限、无数据、服务失败和并发冲突。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/commercial-orders`
  - `POST /api/v1/commercial-orders/{orderId}/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 创作者、项目负责人、团队财务 能从规定入口进入 `商单结算`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。
