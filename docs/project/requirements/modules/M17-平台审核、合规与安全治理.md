## 1. 模块目标与边界

本模块统一承载「平台审核、合规与安全治理」相关需求。模块内页面、接口、数据、权限、异常与验收必须作为同一能力集合维护，不允许只完成可见页面而遗漏服务端规则或失败路径。

- 前置依赖：M09、M15、审计与安全基础
- 下游能力：内容放行、申诉、风控和高危操作治理
- 页面只做范围映射；模块完成必须通过联合验收，不以单页可打开为完成。

## 4. 联合验收要求

本模块并入「D3 审核合规安全闭环」验收，不单独以页面数量结项。验收至少覆盖：

1. 前置依赖真实可用，权限和租户上下文贯穿全流程；
2. 模块内数据对象、状态机、API 和页面展示一致；
3. 正常、空、失败、冲突、取消、超时、重试和恢复路径按适用范围通过；
4. 模块产生的任务、费用、审计、合规和版本证据可以追踪；
5. 下游模块能够消费本模块产物，刷新或重复请求不产生重复副作用。

## 5. 详细功能需求

### AD-003 平台审计日志

- 系统：平台后台
- 路由：`admin/admin-audit-log.html`
- 阶段：P0
- 当前状态：未开始


| 属性 | 规格 |
|---|---|
| 系统 | 平台运营后台 |
| 原型路由 | `admin/admin-audit-log.html` |
| 业务域 | 平台安全治理 |
| 阶段 | P0 |
| 主要用户 | 超级管理员、安全管理员 |

### 页面目标

统一查看后台、用户、团队、项目、任务、扣费、合规敏感操作。

### 入口、前置与退出

- 进入页面前必须验证后台员工独立会话、角色和数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `平台审计日志` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：筛选安全或审计记录
  - 操作：查看变更前后证据
  - 操作：审批或处置高风险动作
  - 操作：按请求 ID、对象和操作者检索日志
  - 字段：日志/审批 ID
  - 字段：操作者
  - 字段：对象
  - 字段：动作
  - 字段：变更摘要
  - 字段：IP/设备
  - 字段：结果
  - 字段：发生时间
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `AdminStaff`
  - `AdminRole`
  - `AuditLog`
  - `ApprovalRequest`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `admin.security.view`
  - `admin.security.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：以服务端会话和权限为准。
  - 禁用态：无权限操作不渲染或禁用并说明原因，接口仍必须拒绝。
  - 异常态：登录风险、验证失败和会话失效不得泄露账号是否存在。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/admin/security`
  - `POST /api/v1/admin/security/actions`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 超级管理员、安全管理员 能从规定入口进入 `平台审计日志`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。
