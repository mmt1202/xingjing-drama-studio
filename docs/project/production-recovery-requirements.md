# 制作恢复与首集交付需求

更新时间：2026-11-12。适用于后续开发，状态均为待实施或待验收，不能作为已完成功能宣传。依据为 v9.2 的制作主流程、CR-091/092/094/095、生成与账务规则；冻结文档保持不变。用户已委托产品取舍，优先保证作品能持续完成，再扩展高级创作能力。

## 第一优先：生成异常后能继续制作

用户目标：刷新、掉线或服务重启后，知道任务是否已经发送、资金占用原因，以及可以安全执行的下一步。

| 场景 | 产品行为 | 完成证据 |
|---|---|---|
| 已占用模型并发额度，但任务尚未提交就发生进程中断 | 记录可追溯的占用身份；能证明未发出的请求自动回收额度；仍有执行可能的请求保持占用。用户无需修改模型并发数字解锁。 | 在取得额度与任务提交之间终止进程，恢复后额度与有效任务一致；多 worker 不重复释放，不影响其他工作区任务。 |
| 供应商调用结果未知 | 任务详情显示“结果待核验”、原始请求时间、已占用费用及不可重新付费的原因。普通用户可查看和刷新；不能把未知当作失败点击新任务重发。 | 超时、断网、重启及重复打开页面均保持同一执行身份；原请求与资金记录没有重复。 |
| 管理员已取得可信结果证据 | 在专用核验页查看任务、固定输入、供应商追踪信息与证据；预览处理影响后，确认“从已存在结果恢复”或“已证实未成功并释放”。无法证明时继续保持未知。 | 权限即时校验、版本冲突、相反证据冲突、同键回放、重复回调及一次结算全部覆盖。供应商结果与本地产物摘要可核对，审计完整。 |
| 上游已完成，本地发布失败 | 明确显示生成已经完成，按钮只恢复产物入库及账务完成，不重新调用模型。 | 供应商请求次数保持一次；文件缺失或摘要不符不能假成功。 |

实施约束：并发占用和资金预留是两种资源，分别记录、分别核验，不能用一个 TTL 同时释放。新占用须绑定稳定请求或任务身份；不根据当前 `activeCalls` 猜测历史任务。旧任务证据不足时列入待核验，不擅自归零。公开页面不展示凭据、原始认证头或其他工作区内容。

## 第二优先：长文本变成可确认的分集方案

用户目标：导入长篇原文后，能看懂每一集来自哪些章节、哪些内容由 AI 改写，并能调整单集而不破坏已完成的制作。

1. 原文以不可变版本保存；章节、片段和文字范围具有稳定身份。导入预览区分识别出的章节标题与正文段落，不把一整段正文直接当作正式集名。
2. 分集建议先生成候选方案，显示集名、来源范围、建议时长及未覆盖片段。用户确认后建立工作稿；不自动重命名、重排或覆盖已经存在的 112 集等真实记录。
3. 映射明确区分“原文精确引用”“人工确认的改编关系”“模型建议待确认”“未映射”。全文相同只能证明全文来源，不能冒充逐场映射或语义理解。
4. 单集生成、重试和采用保留精确的原文版本及范围；失败只重试该部分，不能用截断全文或重新生成整部作品隐藏局部失败。
5. 版本对比可按场景、对白或旁白选择恢复。提交形成新版本，列出受影响的导演/分镜引用；旧冻结分镜、素材、时间线和成片保持原来源。

完成证据：包含重复标题、跨章分集、人工调整、源文后续编辑、局部失败及并发保存的长篇样本；从成片输入可追溯到具体原文版本与范围。显示“候选/未映射”不是完成自动语义映射的证据。

## 第三优先：第一集产物与费用闭环

- 原生视频接入采用持久化供应商 job ID 和固定输入版本。启动和恢复不能借用旧队列的任务身份；重连查询已有 job，不创建另一笔生成。
- 图片、视频、配音、字幕、时间线及成片使用可确认的具体版本。制作过程中给出前置缺失项的直接入口；返回后保留当前集、选择和草稿。
- 在独立验收项目中完成原文 → 剧本 → 导演 → 资产 → 冻结分镜 → 实际媒体 → 音频 → 时间线 → 渲染 → 审核 → MP4 与交付清单。核对重复回调、跨集隔离、预算和最终结算。
- 真实供应商、渲染、支付和发布配置尚未就绪时清楚显示缺失条件。代码可继续实现和隔离验证，实际付费、收退款或对外发布按真实配置与授权执行。

首集通过后才扩大到多集并行和团队交付；同时完成备份实际恢复与故障演练。支付、企业身份、开放 API、外部通知、发布和容量要求仍属于完整产品范围，不因当前优先级而删除。
