## 预算实现前已核实的约束

- 项目预算在 `xingjing_projects.configuration.budgetMinor`，现有界面明示 CNY，但没有币种字段。单集预算仍在 `project.json`，其中 0 是合法零预算，不能与未设置上限混淆。
- 三类生产 hold 已在同一数据库；项目预算占用应按实际消费加 active hold 的剩余预留汇总，不能使用工作区账户的总消费或从导出依赖重复计入共享素材。
- M06 只有 M05 来源能从固定分镜证明单集；M07 任务尚无可靠单集归属；M08 可从固定时间线版本取得单集。完整单集硬限需要 SQL 权威策略和不可变任务归属，不能读取文件后直接声称原子约束已完成。
- 除三类初始冻结外，还须覆盖 M07/M08 原 hold 重新激活，以及预算下调和解除上限的权限与审计。等待锁后再次识别同键已完成请求，幂等回放为零新增占用。
- 共同项目锁、账户锁及现有任务/hold 锁的顺序还需逐路径复核，并用真实 PostgreSQL 并发验证，不把先查总额后保存配置当作消费限制。

## 实际供应商适配的接线约束

- 现有系统配置使用加密的 `provider_credential`，M06 模型定义则只声明 `credential_ref`，尚未解析到原生凭据；WebUI 保存密钥不会自动接通 M06。部署共享凭据与工作区模型授权必须明确绑定，不能悄悄选择另一条 active 凭据。
- 可从 `lib/backend_assembly/assembler.py::assemble_backend` 与 `lib/image_backends/base.py::ImageGenerationRequest` 接原生图片执行器；先做图片生成/参考图编辑，固定 provider/model 和已验证输入。避免整层复用带 legacy 写回、Ledger 与 VersionManager 的 `MediaGenerator`。
- 执行必须持久化认领和确定未发送/提交未知/已完成状态，不能仅开内存后台 task。未知同步调用不能按 TTL 重新付费；本地 execution ID 不能冒充供应商 job ID。
- 产物走 M06 artifact store 和受信任完成事务；明确用户结算策略及版本，不能把供应商美元用量、预估费用或旧 Ledger 扣费重复记为用户实际消费。
- 视频可复用底层 `VideoBackend.generate/resume_video`，但供应商 job ID 持久化需注入 M06 专用回调；现有 mixin 写的是 legacy queue，不能直接传 M06 task ID。
