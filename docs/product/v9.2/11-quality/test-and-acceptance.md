# v9.2 测试与验收规范

## 1. 质量目标

测试不以“页面能打开”为完成标准，而要证明 197 页对应的业务规则、接口、数据、状态、权限、计费和合规闭环成立。

## 2. 测试层级

| 层级 | 责任 | 最低覆盖 |
|---|---|---|
| 单元测试 | 领域规则、转换、计价、权限表达式 | 核心领域分支 ≥ 90% |
| 组件测试 | Repository、MQ consumer、provider adapter、文件探测 | 所有外部边界正常/异常 |
| API 集成 | OpenAPI 契约、鉴权、幂等、并发、事务 | 所有 operationId |
| 状态机测试 | 项目、任务、计费、导出、审核等 | 所有合法边和非法边 |
| 页面测试 | 路由、状态、字段、操作、可访问性 | 197/197 |
| 端到端 | 四端关键用户旅程 | P0 全闭环、P1/P2 核心闭环 |
| 安全测试 | 多租户、IDOR、上传、外链、后台、高危操作 | 所有对象型接口 |
| 性能/容量 | API、列表、任务创建、SSE、队列、媒体 | 达到架构目标 |
| 恢复测试 | DB、MQ、对象存储、缓存、服务故障 | RTO/RPO 达标 |
| AI 评测 | 质量、成本、耗时、失败归因、降级 | 每个生产模型版本 |

## 3. 环境

- CI：单元、组件、契约；使用临时 PostgreSQL/Redis/RabbitMQ/MinIO。
- Integration：完整服务、模拟供应商和测试支付/消息通道。
- Staging：与生产同拓扑、脱敏固定数据、真实模型沙箱/低配额。
- Production：仅冒烟、监控和受控合成探针，不使用真实用户内容做测试。

测试数据按工作区隔离；每次运行创建唯一前缀并可重复清理。账务、审计和合规清理只允许测试环境专用角色。

## 4. 页面通用用例

每页使用追踪矩阵编号 `TC-{PAGE-ID}-01..06`：

| 后缀 | 用例 | 断言 |
|---|---|---|
| 01 | 授权角色进入 | 路由、标题、上下文、字段和数据范围正确 |
| 02 | 未授权/跨租户访问 | 403/404，响应和 UI 不泄露对象信息 |
| 03 | 页面状态 | 加载、空、处理中、成功、失败、冲突均可恢复 |
| 04 | 写操作 | 校验、幂等、乐观锁和保存结果正确 |
| 05 | 审计 | 请求 ID、操作者、对象、结果可检索 |
| 06 | 故障 | 网络/服务失败不丢已保存数据、不重复副作用 |

只读页的 04 改为筛选、排序、分页和导出权限；客户审片页额外验证 token、有效期、版本和下载策略。

## 5. P0 端到端主流程

### E2E-P0-001 从剧本到正式成片

1. 用户创建工作区和项目。
2. 导入合法剧本文档并完成媒体/文件校验。
3. 内容体检和剧本解析生成结构化版本。
4. 确认 AI 导演设定、主体资产和分镜。
5. 批量生成图片和视频，包含一次可重试失败。
6. 生成配音和字幕，完成时间线合成。
7. 查看任务和镜头级算力流水。
8. 冻结项目快照并执行合规检查。
9. 无阻断项后正式导出 MP4。
10. 断言导出包、账务、模型调用、合规和审计记录关联同一项目版本。

### E2E-P0-002 合规阻断

构造缺少权利证明的商用素材，断言预览可用但正式导出返回 `COMPLIANCE_BLOCKED`；补充有效授权并重检后才可导出。

### E2E-P0-003 算力不足与恢复

余额低于 maxCredit 时任务不创建/不入队；充值后使用新幂等键提交成功；没有孤立冻结单。

### E2E-P0-004 批量部分失败

100 个镜头任务中模拟成功、可重试、终止失败和取消，断言汇总、子任务状态、冻结/结算/释放及成本报表一致。

## 6. P1 端到端流程

- E2E-P1-001 团队邀请、角色分配、项目级权限和移除立即生效。
- E2E-P1-002 创建客户外链、密码验证、时间点批注、打回、新版本和确认交付。
- E2E-P1-003 剧本/资产/分镜/成片版本对比与回滚，不覆盖历史。
- E2E-P1-004 剪映/Premiere/DaVinci 导出清单与素材引用完整。
- E2E-P1-005 模板创建、审核、发布、应用和下架对历史项目无破坏。
- E2E-P1-006 订单、退款、发票和对账闭环。

## 7. P2 端到端流程

- E2E-P2-001 Fork 血缘、授权快照和分成规则保持可追溯。
- E2E-P2-002 商单报价、合同、里程碑、交付、打回、验收、结算和争议。
- E2E-P2-003 API 客户端密钥轮换、scope、限流、Webhook 重试和审计。
- E2E-P2-004 市场条目购买/授权后可进入资产库，撤下不破坏历史许可。

## 8. API 契约测试

- OpenAPI 每个 operationId 生成正向和标准错误响应测试。
- 请求缺 workspace、幂等键、If-Match、必填字段时返回规定错误。
- 相同幂等键相同请求返回同一结果；不同请求返回 IDEMPOTENCY_CONFLICT。
- 列表游标稳定，不因同时间新增数据重复或漏项。
- 未知响应字段不破坏客户端；破坏性变更由 API diff 阻断。

## 9. 状态机测试

从 `state-machines.md` 自动生成合法转换参数化测试和非法边测试。重点断言：

- 终态不能被晚回调覆盖；
- 已取消任务不会重新入队；
- 项目内容变化使合规结果失效；
- 新成片版本不继承旧客户批准；
- 商单争议暂停自动结算；
- 归档/冻结项目禁止普通编辑。

## 10. 账务属性测试

使用随机序列执行 grant、hold、settle、release、refund、adjust，始终验证：

```text
available >= 0
settled + released <= hold.requested
account summary == ledger replay
one business operation == at most one effective financial side effect
```

并发测试：同账户 100 个并发冻结、重复回调、结算与释放竞态、晚回调和退款竞态。

## 11. 安全测试

- 用两个工作区对每个对象 API 执行 ID 替换，全部拒绝跨租户访问。
- 客户外链：猜测 token、密码暴力、过期、撤销、锁定、版本越权、禁下载。
- 后台：普通用户 token 访问、员工越权、脱敏绕过、导出越权、审批人分离。
- 文件：伪造 MIME、超大文件、压缩炸弹、恶意 SVG、路径穿越、SSRF URL。
- 回调：签名错误、过期时间、nonce 重放、body 篡改、providerTaskId 不匹配。
- Web：XSS、CSRF、CSP、点击劫持、开放重定向、敏感日志。

## 12. 性能与容量

| 场景 | 负载 | 通过标准 |
|---|---|---|
| 普通读 API | 300 RPS，15 分钟 | P95≤500ms，错误<0.5% |
| 普通写 API | 100 RPS，15 分钟 | P95≤800ms，重复副作用=0 |
| 分镜列表 | 单集 1000 镜头 | 首屏≤3s，滚动无明显长任务 |
| 故事板 | 200 卡片和媒体缩略图 | 懒加载/虚拟化，内存稳定 |
| 批量创建 | 单请求 100 子任务 | 5s 内持久化返回 |
| SSE | 5000 同时连接 | 状态 P95 延迟≤3s，重连恢复 |
| 队列积压 | 10万消息压测 | 不丢消息，扩容后可恢复，账务一致 |
| 导出 | 100 并发长任务 | API 不阻塞，worker 限流生效 |

## 13. AI 模型评测

每次模型版本或路由重大变更运行固定基准集，记录成功率、P50/P95 时延、人工可用率、一致性、成本和错误覆盖。质量未达阈值或成本偏差超过 10% 不得自动替换默认模型。

## 14. 恢复测试

- 任务运行时重启 generation-service，任务不丢且不重复扣费。
- RabbitMQ 节点故障，outbox 最终重新发布且消费者幂等。
- Redis 清空，登录外数据可重建，账务/任务最终状态不丢。
- 对象存储短暂不可用，任务重试并保持元数据一致。
- PostgreSQL 恢复到备份和 WAL，验证 RPO/RTO、账本和审计摘要。

## 15. 发布门禁

- 197 页通用用例全部建立，P0 自动化通过率 100%，P1/P2 对应阶段发布前 100%。
- OpenAPI 校验、破坏性 diff、数据库迁移、SCA、SAST、镜像扫描通过。
- P0 主流程、计费属性、多租户、导出合规和恢复测试通过。
- 不允许以忽略测试、手工改库或关闭合规规则的方式放行。
- 已知缺陷按严重度：S0/S1 为 0；S2 必须有明确规避、负责人和修复版本。
