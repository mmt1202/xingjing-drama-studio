# 团队/企业后台 18 页开发规格

> 基线：XJ-WEB-9.2。页面顺序与 `v9-complete-manifest.json` 一致。每页规格均受全局 API、权限、状态机、计费、合规和测试规范约束。

## TM-001 团队账单

| 属性 | 规格 |
|---|---|
| 系统 | 团队/企业后台 |
| 原型路由 | `team/team-billing.html` |
| 业务域 | 团队计费与成本 |
| 阶段 | P1 |
| 主要用户 | 团队所有者、团队财务、项目负责人 |

### 页面目标

查看团队套餐、席位、算力账户、订单、发票和账务入口，并限制财务数据范围。

### 入口、前置与退出

- 进入页面前必须解析团队工作区及管理员数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `团队账单` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看余额/成本/流水
  - 操作：筛选并导出账务数据
  - 操作：发起有审计的财务操作
  - 字段：账户/流水 ID
  - 字段：业务单据号
  - 字段：金额/算力最小单位
  - 字段：冻结/结算状态
  - 字段：关联任务
  - 字段：发生时间
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `CreditAccount`
  - `CreditHold`
  - `CreditTransaction`
  - `Order`
  - `Invoice`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `billing.view`
  - `billing.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：余额、冻结额和流水使用同一结算快照。
  - 空状态：无流水时展示计费说明，不伪造示例金额。
  - 异常态：对账不平、重复回调或退款处理中显示工单/人工复核编号。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/workspaces/{workspaceId}/billing`
  - `GET /api/v1/workspaces/{workspaceId}/costs`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 团队所有者、团队财务、项目负责人 能从规定入口进入 `团队账单`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

## TM-002 客户审片链接管理

| 属性 | 规格 |
|---|---|
| 系统 | 团队/企业后台 |
| 原型路由 | `team/team-client-link-management.html` |
| 业务域 | 团队客户审片 |
| 阶段 | P1 |
| 主要用户 | 团队管理员、项目负责人 |

### 页面目标

统一管理客户外链、访问权限、水印、有效期和反馈状态。

### 入口、前置与退出

- 进入页面前必须解析团队工作区及管理员数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `客户审片链接管理` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看可审版本
  - 操作：提交时间点反馈
  - 操作：通过或打回受控版本
  - 操作：创建、撤销或复制受控访问链接
  - 字段：审片链接/会话 ID
  - 字段：可见版本
  - 字段：有效期
  - 字段：访问策略
  - 字段：时间点批注
  - 字段：审批状态
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `ReviewLink`
  - `ReviewSession`
  - `ReviewComment`
  - `ApprovalRecord`
  - `FinalVideoVersion`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `review.view`
  - `review.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：验证外链有效期、访问策略和可见版本。
  - 协作态：批注提交后显示时间点、提交人和处理状态。
  - 异常态：过期、撤销、超限、版本删除分别给出明确结果且不泄露项目信息。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/workspaces/{workspaceId}/review-links`
  - `POST /api/v1/workspaces/{workspaceId}/review-links`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 团队管理员、项目负责人 能从规定入口进入 `客户审片链接管理`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。

创建和维护团队角色，配置菜单、动作和数据范围并预览权限影响。

### 入口、前置与退出

- 进入页面前必须解析团队工作区及管理员数据范围。
- 入口可以来自所属一级模块、对象详情、任务/通知深链或具备权限的关联页面。
- 返回列表时恢复筛选、分页和滚动；深链跳转保留工作区与对象上下文。

### 页面区域、字段与操作

- 顶部区域必须展示页面标题、当前上下文、关键状态和主操作。
- 主内容区展示与 `角色权限` 直接相关的数据，不使用与业务无关的通用占位卡片。
  - 操作：查看工作区范围
  - 操作：维护成员或配置
  - 操作：查看变更记录
  - 操作：预览权限影响并保存矩阵版本
  - 字段：工作区 ID
  - 字段：成员/角色
  - 字段：数据范围
  - 字段：席位/套餐
  - 字段：状态
  - 字段：更新时间
- 列表支持服务端分页、稳定排序和组合筛选；详情显示对象 ID、版本和更新时间。

### 数据对象与业务规则

  - `Workspace`
  - `WorkspaceMember`
  - `Role`
  - `Permission`
  - `AuditLog`
- 所有查询按租户和权限范围过滤；跨对象引用校验同一工作区或明确授权关系。
- 写入携带 `Idempotency-Key`；更新携带对象 `version`，冲突返回 `409 VERSION_CONFLICT`。

### 权限与数据范围

  - `workspace.member.view`
  - `workspace.member.manage`
- 前端可见性不能替代服务端鉴权；权限变化后下一次请求立即生效。
- 所有新增、修改、提交、审批、导出、删除或高风险动作记录操作者、时间、对象、变更前后摘要、请求 ID 和结果。

### 页面状态与异常

  - 加载态：以服务端会话和权限为准。
  - 禁用态：无权限操作不渲染或禁用并说明原因，接口仍必须拒绝。
  - 异常态：登录风险、验证失败和会话失效不得泄露账号是否存在。
- 网络重试不得重复提交写操作；恢复后重新读取服务端最终状态。

### 接口依赖

  - `GET /api/v1/workspaces/{workspaceId}/members`
  - `PUT /api/v1/workspaces/{workspaceId}/roles/{roleId}`
- 通用依赖：`GET /api/v1/session/context` 获取当前用户、工作区、角色和功能开关。

### 验收标准

1. 具备权限的 团队所有者、团队管理员 能从规定入口进入 `角色权限`，页面上下文、标题和数据范围正确。
2. 无权限用户直接访问路由时服务端返回 403，页面不泄露对象名称、媒体地址或敏感字段。
3. 页面加载、空数据、处理中、成功、失败和并发冲突状态均有明确反馈和可执行恢复动作。
4. 所有写操作通过服务端校验、幂等和乐观锁；成功后重新读取的数据与提交结果一致。
5. 审计要求覆盖的操作可以按请求 ID、操作者和业务对象检索。
6. 页面接口失败不会丢失已保存数据，也不会产生重复任务、重复扣费或重复审批。
