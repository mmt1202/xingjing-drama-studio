# v9.2 决策登记与外部准入门禁

## 已冻结决策

| 编号 | 决策 | 结论 |
|---|---|---|
| ADR-001 | 产品基线 | v9.2 原型是唯一产品与交互基线 |
| ADR-002 | 客户端范围 | Web 四端；不做原生桌面和原生移动端 |
| ADR-003 | 主数据库 | PostgreSQL，首期单实例多 schema |
| ADR-004 | 业务/AI 边界 | Java 持有业务、权限、计费和审计真相；Python 负责 AI 与适配 |
| ADR-005 | 异步基础设施 | RabbitMQ + outbox + 幂等消费者 |
| ADR-006 | 实时状态 | SSE 起步，详情查询校正最终状态 |
| ADR-007 | 媒体 | 对象存储 + FFmpeg worker，数据库不存二进制 |
| ADR-008 | 计费 | 预估、冻结、实际结算、失败释放，不可变流水 |
| ADR-009 | 合规顺序 | 正式导出前服务端强制合规门禁 |
| ADR-010 | 多租户 | workspace 为租户边界，应用校验 + PostgreSQL RLS 纵深防御 |

## 产品阶段决策

| 阶段 | 页面数 | 目标 |
|---|---:|---|
| P0 | 56 | 剧本到第一集正式成片及必要平台治理 |
| P1 | 121 | 工作室规模化、客户交付和完整后台 |
| P2 | 20 | 市场、Fork、商单、开放 API 等生态能力 |

页面已逐一标注阶段。阶段数量是 v9.2 全量页面的工程规划，不代表单个发布必须同时上线该阶段所有页面；每个版本仍需从对应阶段选择垂直闭环。

## 外部准入门禁

以下事项不能通过编写内部文档替代，但不阻塞使用模拟器开发平台公共能力：

| 门禁 | 负责人 | 未满足时允许 | 未满足时禁止 |
|---|---|---|---|
| 模型供应商合同与 POC | 商务、模型运营、架构 | 适配器、mock、路由和任务系统开发 | 对真实用户开放付费模型 |
| 支付/退款通道合同 | 财务、商务、架构 | 内部算力账本和沙箱订单 | 真实收款、自动退款 |
| 短信/邮件/企业消息通道 | 运营、安全 | stub 和模板开发 | 向真实用户发送 |
| 内容审核供应商或自研规则评测 | 合规、模型运营 | 规则框架和测试集开发 | 依赖未验证结果自动放行 |
| 法务合规意见 | 法务/合规负责人 | 测试环境合规流程开发 | 商用正式导出和外部发布 |
| 对象存储/云区域选择 | 运维、安全、采购 | MinIO 本地和测试开发 | 真实生产数据落地 |
| 企业客户 SSO/私有化合同 | 企业交付、架构、安全 | 标准扩展点设计 | 承诺客户特有协议和 SLA |

## 评审签字要求

- 产品：范围、阶段、逐页目标和验收。
- 设计：页面结构、状态、响应式与可访问性。
- 架构：服务、数据、API、事件和部署。
- AI/模型运营：能力矩阵、路由、成本和 POC。
- 财务：算力、退款、调账和对账。
- 安全/法务：多租户、数据分级、合规规则和保留期。
- 测试：追踪矩阵、自动化范围和发布门禁。

资料评审通过后记录评审版本、参与人、日期、保留意见和生效范围；任何 L3/L4 变更重新触发相关领域评审。
