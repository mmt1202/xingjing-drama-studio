# v9.2 资料治理与唯一事实源

## 1. 目的

本文件解决历史资料版本低于原型的问题，规定开发、测试和评审遇到冲突时如何裁决。

## 2. 权威顺序

| 顺序 | 资料 | 可裁决内容 |
|---|---|---|
| 1 | v9.2 `v9-complete-manifest.json`、`v9.2-menu-fix-manifest.json` | 页面数量、路由、系统归属、一级导航 |
| 2 | v9.2 对应 HTML 页面和系统资源 | 页面标题、可见区域、显式字段、显式操作 |
| 3 | 本开发规格资料包 | 阶段、业务规则、数据、接口、权限、状态和验收 |
| 4 | `PRODUCT_REQUIREMENTS.md` | v9.2 未明确处的业务语义 |
| 5 | 技术架构 v1.0 与后台补充版 v2.1 | 技术方向与服务边界参考 |
| 6 | 更早 PRD、原型、研究报告 | 背景与备选方案，不具有裁决权 |

本资料包发布后，工程实现不得直接引用第 4 至第 6 顺序的资料作为需求依据。

## 3. 版本规则

- 产品基线版本：`XJ-WEB-9.2`。
- 开发规格版本：语义化版本 `9.2.x`，修订不改变原型大版本。
- API 主版本：`v1`，路径前缀 `/api/v1`。
- 事件 schema 版本：每类事件独立使用正整数，从 `1` 开始。
- 数据库迁移：只允许向前追加的版本化迁移，不允许直接修改已应用迁移。

## 5. 术语

| 术语 | 定义 |
|---|---|
| 平台 | 星镜剧创 SaaS 整体 |
| 工作区 | 个人或团队拥有的一级租户边界 |
| 项目 | 一部剧或一个商业制作任务的生产容器 |
| 剧集 | 项目下的单集生产单元 |
| 镜头 | 拥有唯一 ID 的最小分镜与生成管理单元 |
| 主体资产 | 被镜头引用的角色、场景、道具、服装、声音等可复用对象 |
| 故事板 | 镜头、主体引用、提示词、候选图/视频和状态的组合工作单元 |
| 生成任务 | 对文本、图片、视频、音频、对口型或增强模型的一次可追踪执行 |
| 正式导出 | 可用于客户交付或平台发布的不可静默绕过合规检查的导出 |
| 算力 | 平台内部统一计费额度，不等同于供应商原始 token 或 credit |
| 客户外链 | 不授予项目编辑能力的独立审片访问上下文 |

## 6. 冲突裁决

1. 原型与旧 PRD 冲突：以 v9.2 原型为准，并更新本资料包。
2. 页面与 API 冲突：在开发前由产品和架构共同裁决；未裁决前不得自行删除页面能力。
3. 计费或合规冲突：采用对用户资金更安全、对正式导出更严格的规则。
4. 同名字段语义不同：禁止复用字段名，必须拆分并写迁移说明。
5. 外部供应商能力不确定：适配层暴露平台最小能力，供应商特有参数进入 `provider_options`，不得污染公共领域模型。

## 7. 变更流程

变更分为四级：

- L1 文案与样式：设计负责人批准。
- L2 页面字段或非关键交互：产品、前端、后端批准。
- L3 数据、接口、状态、权限：产品、架构、测试批准。
- L4 计费、支付、合规、跨租户访问：产品、架构、安全/法务、测试批准。

每项变更必须记录变更编号、原因、影响页面、影响接口、数据迁移、兼容策略、测试范围和回滚方式。

## 8. 默认工程约定

- ID 使用 UUIDv7；对外以字符串传输。
- 时间使用 UTC 存储，API 使用 RFC 3339，前端按用户时区展示。
- 金额和算力使用整数最小单位，禁止浮点结算。
- 所有可变业务表包含 `created_at`、`created_by`、`updated_at`、`updated_by`、`version`。
- 租户业务表包含 `workspace_id`；平台级表必须明确标记为平台域。
- 删除默认为软删除；账务、审计、模型调用和合规记录禁止物理删除。
- 正式导出前执行合规门禁，不能以 UI 隐藏代替服务端校验。
