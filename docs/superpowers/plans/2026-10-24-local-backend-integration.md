# 正式本地后端接通执行计划

**目标：** 使正常 React 入口使用真实 Java 身份、同库 PostgreSQL 和 Python 业务服务，能够注册、登录、建立工作区、创建并回读项目及各域数据。

**架构：** 沿用现有双后端。Java 的 JDBC URL 与 Python 的 asyncpg/psycopg URL 指向同一物理库，identity/public schema 分工保持不变。配置和本地稳定密钥保存在 Git 忽略的 `.env.local`，显式进程环境与 `.env` 优先；提供持久启动工具，不依赖临时 PreviewGateway、虚拟身份或演示业务种子。

**验证：** 不创建或修改测试文件、测试脚本、夹具或快照。运行必要已有回归、静态检查和构建；对实际 Java/PG/Python 发起请求并在正式浏览器入口操作。外部支付、模型、审核及渲染缺配置时明确不可用，不能伪造成功或报价。

- [x] 核对身份、数据库、前端代理与生产 Runtime；确认 Docker 启动故障及缺少正式连接配置。
- [x] 用户打开 Docker，PostgreSQL/RabbitMQ/MinIO 健康；保留原数据卷，创建独立干净业务库 `xingjing_platform`。
- [x] 配置同库、实际存储目录和稳定本地密钥；Java Flyway 后运行 Python Alembic，核对实际版本。
- [x] 修复 Java 成员首次访问的动态权限投影顺序，保留已有撤权/自定义角色。
- [x] 修复登录上下文确认与切工作区失败处理，补齐媒体 Bearer 鉴权。
- [x] 编辑领域读取/时间线保存与外部渲染执行分离；缺渲染或报价不写任务/扣费/假结果。
- [x] 提供 `scripts/local_platform.py` 启动/状态/停止工具，Windows 隐藏进程、同库校验、日志、就绪检查和自有 PID 管理。
- [x] 正式入口注册/登录、工作区、项目创建/保存/回读、主要页面读取及跨工作区拒绝；不自动创建管理员或财务权限。
- [x] 完成相关已有回归、静态/构建及迁移核验；更新接通证据和启动文档，并实际验证启动工具停止/重新启动后项目仍可读取。

核对后纳入正式启动所必需的八项既有迁移修正和 Java RestClient 依赖，其余无关未提交文件保持原样；不重置 Docker、不删除数据卷、不将旧预览构造库作为正式默认数据库。
