# 剧本逐场来源映射交付记录

日期：2026-11-13。范围为 CR-092/093/094 的人工确认来源映射及版本化保存基础，关联 CR-095 的版本比较与整版恢复。模型语义建议、局部恢复、AI 长文本编排及实际成片联合验收仍未完成。

## 已交付的用户路径

- 剧本工作流的“原文映射”支持选择版本、场景或动作/对白/旁白，按全部、已映射、待确认筛选。原文可按章节定位、分页阅读、查找同文和拖选片段；Unicode 码点坐标包含起点、不含终点，表情字符不造成偏移。
- “原文直引”仅用于段落，服务端验证所选规范化原文与段落正文完全一致；“改编取材”由用户明确确认，可填写说明。重复文字列出候选位置，不自动推断真实来源。每个对象可保留一段连续取材范围；未映射对象仍待确认。
- 来源来自单集建立时的不可变快照和取材区间。旧文档没有整本快照时，明确使用自身不可变导入原文，不伪造整本小说关联。旧原文后续变化不替换已有来源快照。
- 确认保存为新剧本版本，保留对象摘要、来源摘要、位置、章节身份、确认人和时间。历史版本只读；冻结禁止修改。正文变化后不沿用位置相同的旧映射，正文未变的版本保留确认记录；整版恢复带回对应映射。
- 版本比较可以识别映射变化。冻结版本下游快照携带该版的映射；旧版无映射时保持原下游字段形状，避免改变已有引用。
- 本地调整保存在当前登录账号、工作区、项目和文档的浏览器会话中。确认有独立核对步骤；网络结果未知保留原键和完整内容，刷新只读取，明确重发才恢复。版本冲突不覆盖，放弃需明确确认，撤权隐藏缓存正文及对象。

## 数据与保存修复

- 增加 ScriptVersion 的不可变来源映射 JSON，以及独立确认回执。每次读写和重发重新检查租户、工作区、项目及权限；更新按剧本修订号和内容版本核对。剧本锁、版本、审计及回执在同一 SQL 事务提交。
- 并发相同请求只创建一个版本；不同请求不能覆盖同一修订；已确认请求即使后来改稿或冻结，仍返回原确认结果。回执写入故障会回滚版本和审计。
- PostgreSQL 直接复现了既有结构化剧本保存的外键问题：缺少 ORM 关系排序时，对白可能先于所属场景插入。仓储按文档、版本、场景、段落的顺序 flush，保留同一事务；不更改测试文件。
- GET/POST `/api/v1/projects/{projectId}/scripts/{scriptId}/provenance-mapping` 为专用读取和确认入口。界面和错误同步提供 zh/en/vi。读取原文每页最多 4000 码点，同文最多返回 50 处，单版最多确认 2000 个对象。
