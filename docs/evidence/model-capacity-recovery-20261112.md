# 生成请求中断与模型额度恢复

日期：2026-11-12。范围为制作异常恢复的第一批：新任务的模型额度、费用预留与任务记录保持一致。未知结果的管理员核验操作和真实供应商联合验收仍未完成。

## 问题与处理

原调用先在模型库提交 `active_calls + 1`，再保存任务及资金预留。实际复现了两次提交之间进程中断后，没有任务却永久占用一个模型名额；并发上限为 1 时后续请求被拒绝。证据：`.tmp/route-admission-before-20261112.log`。

- 生产入口先选择模型和报价，任务、费用及任务绑定的模型占用在同一事务中提交。事务内再次检查模型版本、有效价格、路由策略和并发额度；不再先独立占用名额。
- 新表记录工作区、项目、任务、请求摘要、报价版本和释放身份。原生图片复用已有执行身份，网关任务使用稳定任务身份；同键回放不会再占一份额度。
- 网关发送前持久化“开始提交”。网络错误或结果超时保持原任务、费用及名额；本地超时不能证明供应商没有受理。原请求恢复使用原任务和原键，不重新选择模型或再占名额。
- 已取得明确终态但释放中断的网关任务由恢复扫描补齐；释放身份保证多进程只扣减一次。原生图片沿用其已有执行恢复流程，避免两种扫描互相抢处理。
- 有未释放绑定记录时，健康上报不能覆盖任务持有的并发数；旧版无身份释放也不能将计数扣到有效绑定数量以下。
- 任务详情新增三语“结果待核验”、开始提交时间和保留费用的解释。模型或价格在提交前变化时明确告知此次没有创建任务或预留费用。
