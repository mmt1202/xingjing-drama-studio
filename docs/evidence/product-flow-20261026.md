# 创作流程的状态、恢复与导演确认

## 产品决策

本批次从当前真实项目的使用问题推进：结构化解析失败后，页面把明确失败当成结果不确定，禁用了全部工作流导航；导演生成直接覆盖可变配置，用户无法确认采用哪一版；分集标题直接截取段落首行，正文与分隔线进入了集数选择器。

| 用户目标 | 交付约束 |
|---|---|
| 开始结构化、改写或导演生成前知道能否使用 AI | 从实际项目配置检查文本模型能否在本地准备。配置检查不调用供应商，不承诺凭据有效、余额足够或网络联通；失败仍可手动编辑。 |
| AI 失败后继续工作 | 服务端明确记录失败且尚未应用剧本版本时解除不确定状态；网络中断、通用服务错误和仍在执行的请求继续保留恢复边界。同一操作重试保留请求身份。 |
| 手动处理普通小说 | 展示可复制的标准剧本格式示例和当前版本结构提示；不自动改写正文，不将导入成功或确定性切分描述为语义分析成功。 |
| 选择导演方案再制作 | AI 与手工保存均创建候选；只有与已冻结剧本匹配的最新完整候选可人工确认。历史候选只读，重新采用需先复制为新候选。 |
| 修改方案而不改变已经制作的分镜 | 新候选需要重新确认；旧确认记录与下游已记录的来源保持不变。新智能分镜使用明确确认的导演版本，来源随分镜与冻结快照保存；手工导入及历史无来源记录不伪造确认。 |
| 在多集项目中定位当前集 | 拆分预览避开纯分隔行，标题与列表显示保持有界；不重写既有标题，不改变原文范围、摘要或已保存分集。 |

## 验证范围

- 不创建、修改测试文件、测试脚本、fixtures 或 snapshots。验证使用已有检查和临时进程内断言，隔离数据保留在忽略目录。
- AI 准备检查与失败分类：33 项隔离 SQL/HTTP 断言已通过，包括无调用、无请求写入、无新剧本版本、三语错误、权限与项目范围，以及配置故障和供应商失败的区别。
- 修改前只读保存了正式项目的 7 份剧本文档与 112 集记录摘要，收尾核对来源、版本、修订与生产绑定。
- 导演总控门禁：10 项真实隔离 SQL 断言通过，覆盖无候选、未确认、有效确认、缺权限、跨工作区／项目、解冻、来源摘要变化和新候选失效。
- 分集标题：18 项 Python 与 8 项 TypeScript 断言通过；新旧拆分结果的范围、原文拼接与全部非标题字段保持一致。
- 配置检查只读链：14 项临时旧格式项目检查通过，模型选择仍遵循项目覆盖配置；文件列表与摘要未变化，不调用模型。TextGenerator、factory、旧样式迁移的 23 项已有用例通过。
- AI 请求认领：20 项 SQL 检查通过，超过 6 分钟、24 小时或 365 天的 running 请求均不重复认领；明确失败可重试，成功结果可回放，范围与指纹冲突受控。
- 前端：21 项 React/JSDOM 行为断言和 7 项已有 pages/api 用例通过。全库 lint、类型检查与生产构建通过；全量测试 1832 通过／25 项此前已批准的失败。
- 后端：全库类型检查 69 errors／1079 warnings，与基线一致，本次修改文件没有 error；分层契约 1 kept／0 broken；三语一致性 12 项通过；25 份冻结需求文件摘要不变。
- 已有测试的全局初始化会尝试连接无关财务数据库，部分专项使用 --noconftest 或模块 --confcutdir 及工作区独立临时目录运行；不据此宣称全量 pytest 通过。
- 导演与智能分镜联合验证：真实隔离 SQLite／HTTP 候选保存、剧本冻结、候选确认、分镜生成与冻结链路通过；新增候选和资产版本后，同请求恢复保留原输入，新请求要求重新确认，旧分镜未变。恢复与隔离阶段 16 项断言通过；另有 30 项独立 Smart 幂等／旧冻结摘要兼容检查通过。
- 新迁移隔离重复升级与历史数据保留 9 项断言通过，PostgreSQL DDL 编译通过。M05 已有测试 34 项通过；M03 已有测试 23 通过／1 失败，失败仍要求未经确认的导演配置进入下游，与显式确认规则冲突，未改动该测试。
- 正式本地 PostgreSQL 已升级到 `d2a7aa12000c`，新增表可查询；迁移前由现有启动器备份并验证归档 `postgres-3903c352733e454a.dump`。Java 身份服务、FastAPI 与 Vite 均健康。
- 正式只读 API 核对：7 份剧本的原始文档、所有版本、修订号、冻结版本与导演配置摘要不变；112 集完整投影逐项相等。两个导演新表均为空，没有向实际项目保存验收候选或确认。
- 正式浏览器验证：模型未配置显示明确原因并禁用 AI 提交；手动工作副本正文可编辑，格式指引不替换正文；导演候选草稿阻止切换，明确放弃后恢复导航。导演页面只保留一个依状态选择的下一步，分集管理作为辅助入口。页面控制台无 error。截图保存在本地 `output/product-flow-20261026/`，未提交用户项目内容。
- 真实模型准备结果为 `configuration_unavailable`；此次未配置凭据或调用外部模型。成功的导演确认与 Smart 生成链路来自隔离数据库及注入模型，不能当作真实供应商验收。

## 本地环境恢复

收尾时发现原有服务进程及 Docker 引擎已停止。Docker 重现推理／Secrets Engine socket 的 Windows Error 1920；仅将已核实只含运行 socket 的目录重命名为时间戳备份，未改设置、权限、镜像或数据卷。后续 Docker 启动恢复，引擎检查成功，再由项目现有启动器备份数据库、迁移和启动服务。该恢复不代表已修复 Docker 自身缺陷。

## 仍然未完成的生产能力

- 长文本语义分章、局部回滚与自动编排。
- M05/M06 精确资产版本解析到真实供应商输入；资产版本的 JSON 摘要不能当作图片二进制摘要。
- M09 按当前成片实际引用的任务核对结算，及跨集共享素材成本归属。
- 原子预算限制、真实供应商到最终成片的联合验收与发布回执。
- 执行中断但供应商结果未知的 AI 请求不按时间自动重提，需要核验；该保护不等于已经提供自动取消或管理员核验工作台。
- 历史智能分镜请求若没有持久化原始输入，无法安全重建来源；恢复时明确拒绝推测，但已有历史分镜仍可读取。

本轮不配置供应商凭据、不调用付费模型、不改变真实项目的剧本或生产内容，也不把隔离验证结果展示为正式生成结果。
