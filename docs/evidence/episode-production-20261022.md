# 逐集生产绑定与批量分镜、发布包

- 日期：2026-10-22
- 需求：CR-029 / CR-030；关联 M03 冻结剧本、M04 资产、M05 分镜、M08 成片、M09 正式交付。
- 变更基线：`c97d96da`。
- 状态：实现与本地验证完成；真实服务联合验收和对外发布回执未完成，需求保持开发中。

## 实现

- 在既有 `project.json` 分集账本的 `production` 中记录 `scriptVersionId`、`assetSnapshotId`、`finalVideoVersionId`，没有新增第二份剧集数据。复用自动保存、版本摘要、幂等回执、SQL 审计与 outbox。
- 服务端只列出当前可信工作区/项目的冻结剧本、资产来源、成片、分镜、合规与交付记录；按模块读取权限裁剪候选项。界面使用服务端实际权限启用操作，不从页面角色推断其他模块权限。
- 冻结剧本版本不能同时绑定两集；资产快照的项目、工作区、剧本版本和正文摘要必须匹配；成片必须通过时间线的稳定 `episode_id` 归属当前集。M05 生成入口同样验证资产快照与冻结剧本的对应关系。
- 绑定冻结剧本后保护标题及原文范围；已有分镜的剧集锁定剧本和资产输入。成片候选仅包含本集渲染版本。复制结构不继承生产绑定。
- 新增 `GET /api/v1/projects/{id}/episodes/production` 和 `POST /api/v1/projects/{id}/episodes/production/prepare`。批量准备要求 `If-Match`、项目管理权及相应分镜/导出权限，每批最多 50 个不同集号。
- 批量执行按所选顺序逐集调用既有 `shots/actions` 的 `generateShots` 或正式 `exports` 的 `publish_package`。每集使用自己的冻结输入或成片版本及稳定幂等键。已有结果跳过；缺少前置材料、服务失败分别反馈；失败不阻断其他集。
- 批量操作由当前页面逐集执行，不是离开页面后持续运行的后台批处理任务。离开后未发出的项目停止执行；重新选择重试会根据已有记录和幂等键恢复。
- 待审与发布包指标、剧集表格状态、分镜数量从实际关联记录读取；发布包成功不表示已对外发布。没有发布回执时不显示虚构的已发布统计。
- 查看本集分镜携带 `episodeId`；查看交付携带 `episodeId`、`projectVersion`、`target`。路由使用 Wouter 的 `useSearch` 读取查询参数，避免把查询串从仅含路径的 `useLocation` 中解析。依据已安装代码及 [Wouter 文档](https://github.com/molefrog/wouter#usesearch-query-strings)。
- 新增界面文本同时提供 zh/en/vi，生产目录读取失败及批量失败提供明确提示，未保存编辑期间禁止批量执行。

## 多集导出配置与迁移

原正式导出配置键只有租户、工作区、项目、目标；对下一集进行合规检查会覆盖上一集配置。现在追加不可变 `snapshot_version`，读取和 upsert 均按目标与成片版本定位。版本一致性、审核、授权、结算、AIGC 和商业导出门禁保持有效。

- 迁移：`8e2a4c6d901f`，前序 `7d174f942017`。部署时先执行 `uv run alembic upgrade head`，再启用新服务；本次没有修改实际项目数据库或生产环境。
- 升级保留既有配置。迁移可识别已经使用新键的数据库；不会重复改键。
- 若同一目标已存在多个版本配置，降级明确拒绝，不静默删除其他集的审核配置。
- M02 与其他生产模块使用同一个已迁移权威数据库，沿用部署模板的配置方式；模型和正式导出仍依赖相应模块的真实运行配置。
