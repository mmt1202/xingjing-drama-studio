# 长文本来源与候选分集交付记录

日期：2026-11-13。范围为 CR-029、CR-090/091/092/094 的章节来源和候选确认基础；不代表逐场语义映射、局部版本恢复或真实 AI 长篇改编已经完成。

## 产品行为

- 分集编辑器选择真实原文、章节和集数，先生成持久候选。规则按章节和段落划分，明确不等同 AI 情节改编。标题、时长、采用条目和原文范围可以调整；确认前可逐集读取来源片段。
- 来源规范化为 NFC、LF 和 Unicode 码点坐标；不可变 SQL 快照保存当时原文、摘要和章节身份。重复标题独立，支持中英越标题及“正文第一章”等常见小说格式，不改写原文。正式长篇只读检查识别 102 个章/集标题及一个前言片段。
- 对整份来源求未覆盖区间，补齐“中间章节已分配，前面的内容却被跳过”的问题。非连续区间不能伪装成一个连续范围；候选集数不足、越界或重叠均拒绝，不静默丢失原文。
- 显式确认后追加分集并建立对应 SQL 原文工作稿。原分集对象、标题、顺序、预算及制作引用保持原样。新工作稿仍需改编、结构检查及冻结；确认不调用模型，也不增加预算额度。
- 每个工作稿关联来源快照、章节及范围，原文映射页可以读取旧来源。当前原文变化不会替换已存快照。整集取材证明与逐场/对白改编映射明确区分；历史工作稿没有快照时如实显示。
- 以 SQL 项目锁、文件锁、唯一确认记录和持久文件回执恢复跨存储中断。文件成功而 SQL 失败时，其他编辑和新建工作稿被阻止；发起者可从服务端取回原键和原候选，补齐工作稿、审计和 outbox，不重复建集。
- 页面先保存待确认请求；刷新只读取，结果不确定时显式重发原键与原内容。未保存调整及确认界面保护导航。撤权隐藏缓存并忽略旧读取响应。候选只展开当前编辑项，避免 200 集和 4096 章节产生重复巨型表单。
- 待恢复方案置顶，不被最近 50 份限制隐藏；历史记录显示时间及待恢复状态。已确认方案展示各集准确的剧本入口。

入口：`/app/workspaces/{workspaceId}/projects/{projectId}/episode-split-editor`；工作稿的 `source-mapping` 页面显示取材快照。

## 实现边界

- `lib/source_structure.py` 负责章节、覆盖与规则分集；`server/xingjing_source_planning/` 负责 SQL 来源、候选、权限和确认；既有 `episode_editor` 保持生产账本与派生文件真相源。
- 计划确认权限同时需要项目及剧本查看/管理。每次读取、确认及同键重发重新经过可信工作区与项目范围校验；当前账号不扩权。
- 新增 GET/POST `episode-plans`、来源章节读取、候选详情及确认、固定来源片段读取、工作稿来源查询。请求体严格校验，错误及页面具有 zh/en/vi 文案。
- 文件回执独立于既有最近 50 次普通编辑回执，防止 SQL 恢复证据被正常编辑淘汰；未完成确认必须先恢复。未自动替其他发起者接管中断请求，也未实现历史原文快照补造。
