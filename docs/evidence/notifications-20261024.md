# 站内通知正式界面与偏好验证（2026-10-24）

## 范围与实现

创作者工作区与项目公共壳接入独立 `frontend/src/xingjing_notifications` 模块，复用 `server/xingjing_tasks_runtime/runtime.py` 的正式通知、已读和偏好接口，不建立另一套前端通知真相源。

- 顶栏铃铛读取服务端未读数，提供全部/未读筛选、分页、逐条已读和全部已读。打开面板不会自动标记已读；全部已读针对当前收件人在当前工作区的全部未读记录，不限本页。
- 分页采用 `created_at DESC, id DESC` 稳定顺序；页面、过滤后总数和未读总数在同一 SQL 语句快照内读取，空页也保留真实统计。
- 面板关闭时每 60 秒读取摘要，打开时每 30 秒同步；页面隐藏时暂停，重新可见或聚焦时读取。请求取消、监听器及计时器清理随组件生命周期执行。
- 通知偏好支持 email/sms/push。读取返回实际记录、更新时间和内容版本摘要；首次保存使用 `expectedVersion: null`，后续使用读取到的版本。冲突返回 409，保留编辑并提供显式放弃/重读；相同目标状态的重复 PUT 不追加重复审计。
- 通知已读变更和偏好变更在业务事务内写审计，偏好审计不保存接收目标明文。保存偏好不表示外部消息已经发送或送达。
- 中文、英文、越南文覆盖加载、空状态、权限、登录失效、工作区变化、失败重试、409、偏好表单及对象摘要。

实现文件为 `NotificationCenter.tsx`、`contracts.ts`、`api.ts`、`i18n.ts`、`notifications.css` 及既有 tasks runtime；公共壳只提供组件槽位。无新增数据库表或迁移。

## 身份、范围与对象定位

站内通知继续按可信租户、工作区和当前收件人过滤，要求 `workspace.view`；API Key 明确拒绝。通知接口检查预期工作区和操作者，拒绝项目范围头，成功回执携带实际 `meta.scope` 供客户端核对。

`GET /api/v1/notifications/{id}/target` 首先证明该通知属于当前收件人，再定位受支持的真实对象：

- 项目对象返回结构化项目 ID，由前端构造工作区内总控地址，不接受 metadata 中的任意 URL。
- S04 通用任务显示实际任务摘要，不把它的 ID 冒充 M06 生成任务。摘要不包含任务 payload/result；存在可读项目时提供总控交接。
- 项目目标还要求当前项目/领域读取权限。普通成员检查同源项目分配、工作区与分配权限交集，以及明确完整项目 scope；未知、混合、剧集或镜头窄范围拒绝，不扩大为全项目。
- 已失去权限、对象不存在或不支持定位时明确失败，不伪造详情。

客户端使用共享认证 transport；同一会话的 token 轮换保留通知界面和偏好草稿，登录边界或工作区变化销毁原作用域状态。未保存编辑通过公共导航 guard 与离开页面保护处理。

## 保留边界

- 真实外部邮件、短信、推送 worker、通道账号、供应商回执及送达率未在此切片验收；偏好表单不代表这些渠道已经接通。
- 正常业务库没有为了截图或未读徽标写入模拟通知，也未执行付费模型、收款、退款或消息发送。
- 正式浏览器使用真实空收件箱；带通知内容的逐条处理、偏好并发 409 和对象定位由上述隔离 ASGI 检查验证，未将其描述为实际用户消息的浏览器验收。
- 没有创建或修改测试文件、测试脚本、夹具或快照。站内通知切片完成不替代通用外部投递及整个平台联合验收。
